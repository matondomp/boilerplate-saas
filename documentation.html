Parte 1: Manual de Integração e Onboarding Técnico

1. Visão Geral da Arquitetura e Decisões de Design

Padrão Monólito Modular

A aplicação isola os domínios em módulos contidos em app/modules/. A pasta de extensões (app/modules/addons/) abriga domínios como accounting e crm. A regra de dependência exige que a comunicação entre diferentes módulos ocorra preferencialmente via eventos ou contratos abstratos expostos em shared, mantendo baixo acoplamento.

Camadas de Clean Architecture

Cada módulo é estruturado internamente em:

  • domain/: Entidades puras, regras de negócio, erros e eventos. Sem dependências externas.
  • usecases/: Casos de uso de aplicação (orquestradores). Conhece apenas o domínio e as portas (interfaces).
  • framework/: Controladores HTTP, Rotas, Persistência (Models Lucid, Repositórios e Mappers) e Listeners de eventos.

Tratamento de Erros com Either/Result

O tratamento usa o padrão funcional Either<L, R> para retornar falhas estruturadas (Left) ou sucessos (Right), evitando o uso excessivo de try/catch.

// Exemplo de erro estruturado
export class AccountingOfficeNameRequiredError extends Result<DomainError> {
  constructor() {
    super(false, {
      message: 'accounting.office.name.required',
      error: AccountingOfficeNameRequiredError.name,
    })
  }
}

2. Ciclo de Vida do Registro de Módulos (Bootstrapping)

O AdonisJS detecta e registra dinamicamente rotas, inicializações, eventos e traduções.

// start/main.ts - Bootstrapping dinâmico de arquivos
const loadFiles = async (path: string, pattern: any) => {
  const req = loadContext(path, true, pattern)
  for (const filename of req.keys()) {
    await import(filename)
  }
}

const paths = ['app/modules']
for (const path of paths) {
  await loadFiles(resolve(app.appRoot.pathname, path), /main\/events\.(ts|js)$/)
  await loadFiles(resolve(app.appRoot.pathname, path), /main\/startup\.(ts|js)$/)
  await loadFiles(resolve(app.appRoot.pathname, path), /main\/routes\.(ts|js)$/)
}

Parte 2: Plano de Implementação - Novo Módulo (Pedagogy)

1. Objetivo

Implementar a gestão de Pautas, Alunos, Chamadas e Planos de Aula sob as diretrizes do Ministério da Educação (MED) em Angola.

2. Regras de Negócio do Módulo

Regra Descrição / Fórmula
Componentes de Notas MAC (Avaliação Contínua), NPP (Prova do Professor), NPT (Prova Trimestral)
Média Trimestral (MT) MT = (MAC + NPP + NPT) / 3
Média Final (MF) MF = (MT1 + MT2 + MT3) / 3
Critérios de Aprovação MF >= 10: Aprovado
7 <= MF <= 9: Recurso
MF < 7: Reprovado
Chamadas e Faltas Presença, Falta, Falta Justificada. Alerta visual quando faltas superarem 20% das aulas.

3. Detalhes das Entidades de Domínio

StudentEntity

Representa o aluno no sistema com validação obrigatória de Nome e Matrícula.

GradeEntity

Garante que notas estejam entre 0 e 20 (através do Value Object AcademicGrade) e realiza os cálculos automáticos de médias.

LessonPlanEntity

Define a estrutura pedagógica do plano de aula (Unidade Temática, Tema, Objetivos Operacionais, Métodos, Tarefas e Fases da Aula).
